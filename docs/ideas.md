## 1. Forgiving Question Validation (P0)

### Problem
When a user submits an invalid question (a typo, an open-ended question like *"What is the capital?"*, or unparseable input), the system correctly marks `valid: false` with an explanation. However, both the backend (`server/countrydle/__init__.py:680-688`) and the frontend client store (`client/src/stores/gameStore.ts:238`) **still decrement `remaining_questions` by 1**.
In Wordle or Globle, invalid inputs shake the input box and cost nothing. Penalizing a player's strict 5–10 question daily budget for a typo creates significant player frustration.

### Proposed Solution
1. **Backend**:
   - In `POST /{mode}/question`: If `question_create.valid is False`, do **not** invoke `game_rules.process_question(...)` and do **not** increment `state.questions_asked` or decrement `state.remaining_questions`.
   - Return `{ "valid": false, "question": null, "answer": null, "explanation": "..." }`.
2. **Frontend (`gameStore.ts`)**:
   - When receiving `valid: false`, do not decrement `gameState.remaining_questions`.
   - Trigger a warning toast (`react-hot-toast`) with the explanation (e.g., *"Please ask a yes/no question"*).

## 2. Securing the `/reveal` Endpoint (P0)

### Problem
In `server/{mode}/__init__.py`:
```python
@router.get("/reveal", response_model=CountryDisplay)
async def reveal_country(user: User | None = Depends(get_current_or_guest_user), ...):
    day_country = await CountrydleRepository(session).get_today_country()
    if user is not None:
        state = await CountrydleStateRepository(session).get_state(user, day_country, ...)
        if state and not state.is_game_over:
            raise HTTPException(400, "Cannot reveal country before game is over.")
    return country
```
For unauthenticated guests (`user is None`), the check is completely skipped. Any visitor can open browser DevTools, call `GET /countrydle/reveal`, and instantly view the daily secret entity without playing.

### Proposed Solution
- Require proof of game completion:
  - For authenticated users: Keep the database `state.is_game_over` check.
  - For guests: Either deprecate unauthenticated `/reveal` and only reveal the entity inside the final `POST /{mode}/guess` payload when `guesses_made >= max_guesses` or `won is True`, or verify client guest state before returning the answer.

## 3. Question Plan Caching (P1)

### Problem
Every user question incurs a round-trip to the Google Gemini API (`gemini_json`), adding **1,000ms–1,500ms** of latency per question. In daily geography games, **70%–80% of all players ask the exact same initial questions**:
- *"Is it in Europe?"* / *"Czy leży w Europie?"*
- *"Does it border the ocean?"* / *"Czy ma dostęp do morza?"*
- *"Is the population greater than 10 million?"*
- *"Is it on the East Coast?"*

The AST execution plan generated by Gemini is completely independent of today's target entity (the target is only queried during the SQLite execution step).

### Proposed Solution
Implement an in-memory LRU cache or Redis cache for question plans:
```python
# Key: (mode_name, normalized_question_text)
# Value: QuestionPlan
PLAN_CACHE = TTLCache(maxsize=10000, ttl=86400 * 7)
```
- **Impact**: For cached questions, response latency drops from **`1,200ms` $\rightarrow$ `<3ms`** (~400x speedup), and Gemini API costs drop by 70–80%.

## 4. Database Connection Lifecycle Optimization (P1)

### Problem
In FastAPI route definitions (`POST /{mode}/question`):
```python
@router.post("/question")
async def ask_question(..., session: AsyncSession = Depends(get_db)):
    # 1. DB connection checked out from pool here
    await analyze_and_answer_locally(...)  # 2. Awaits Gemini HTTP call for 1.2s while holding DB conn!
```
Holding an active database connection while waiting on an external network I/O call (Gemini API) exhausts the database connection pool (default: 5–15 connections). 15 concurrent users asking questions will starve the connection pool, causing timeouts on `/state`, `/login`, and the frontend.

### Proposed Solution
- Resolve the Gemini plan *before* checking out a database session, or acquire the session with an explicit context manager (`async with AsyncSessionLocal() as session:`) only during the persistence and state update phase.

## 5. Target Entity Cooldown Window (P1)

### Problem
In `server/db/repositories/*.py`:
```python
select(Wojewodztwo).order_by(func.random()).limit(1)
```
All modes pick daily targets with pure random selection. For Polish Voivodeships (16 total), the probability of the **same voivodeship being selected two days in a row is 6.25% (1 in 16)**, and repeats within 3–4 days are common.

### Proposed Solution
Add a cooldown exclusion window when generating daily targets:
```python
recent_entity_ids = select(DayEntity.entity_id).order_by(DayEntity.date.desc()).limit(cooldown_days)
select(Entity).where(Entity.id.not_in(recent_entity_ids)).order_by(func.random()).limit(1)
```
- **Cooldown Windows**:
  - Województwa (16 items): Exclude last 10 days.
  - US States (50 items): Exclude last 25 days.
  - Countries (~195 items): Exclude last 60 days.
  - Powiaty (~380 items): Exclude last 90 days.

## 6. Unified Streak Engine (P2)

### Problem
- In `server/utils/__init__.py`, `check_streaks()` only checks and resets streaks for `Countrydle`.
- In `wojewodztwodle.py:244`, `us_statedle.py:240`, and `powiatdle.py:255`, streaks are hardcoded as `streak=0  # TODO: Implement streak`.
- Users playing Województwodle, Powiatdle, or US Statedle never accumulate streaks on their profile.

### Proposed Solution
- Generalize the streak calculation in `server/utils/__init__.py` across all four game state models (`CountrydleState`, `WojewodztwodleState`, `PowiatdleState`, `USStatedleState`).
- Store per-mode streak counters or an aggregate player streak in PostgreSQL.

## 7. Frontend Route Code-Splitting (P2)

### Problem
Vite compiles all pages, components, and large SVG map datasets into a single bundle (`dist/assets/index-*.js`, **811 kB minified / 244 kB gzip**). A visitor who only wants to play Countrydle is forced to download the map logic for all 380 Polish Powiaty and 50 US States on initial page load.

### Proposed Solution
Enable route-level code splitting in `client/src/App.tsx`:
```tsx
import { lazy, Suspense } from 'react';

const GamePage = lazy(() => import('./pages/GamePage'));
const PowiatyGamePage = lazy(() => import('./pages/PowiatyGamePage'));
const USStatesGamePage = lazy(() => import('./pages/USStatesGamePage'));
const WojewodztwaGamePage = lazy(() => import('./pages/WojewodztwaGamePage'));
const LeaderboardPage = lazy(() => import('./pages/LeaderboardPage'));
const ArchivePage = lazy(() => import('./pages/ArchivePage'));
```
- **Impact**: Reduces initial bundle size by **~55–65%** down to ~280 kB, boosting Mobile Lighthouse scores and decreasing Time to Interactive (TTI).

## 8. Interactive Map-to-Guess Interaction (P2)

### Problem
Currently, clicking an entity on the map only toggles elimination styling (red/gray). To actually make a guess, the user must manually type the entity name into the text input box.

### Proposed Solution
- Add a lightweight popover or direct "Guess this entity" action when clicking a map polygon:
  - *"Selected: Małopolskie — [Eliminate] or [Submit Guess]"*
- Allows fast, frictionless touch play on mobile devices without opening the virtual keyboard.

## 9. IP-based Rate Limiting on Questions (P3)

### Problem
`POST /{mode}/question` is unthrottled. Automated scripts or malicious actors can spam requests and rapidly exhaust the Google Gemini API quota or incur unexpected costs.

### Proposed Solution
- Introduce `slowapi` (FastAPI rate limiter) or an in-memory Redis sliding-window limiter:
  - Example policy: `15 questions/minute` per IP address for guests, `30 questions/minute` for authenticated accounts.
  - Return `429 Too Many Requests` with a clear retry header.

## 10. Distributed Locking for Midnight Scheduler (P3)

### Problem
APScheduler runs in-process inside Uvicorn. If Countrydle runs multiple worker processes (`workers > 1`) or scales horizontally across container replicas in production, every process will simultaneously execute `generate_day_countries` and `check_streaks` at midnight UTC, causing database lock contention or duplicate day generation.

### Proposed Solution
Wrap the scheduled jobs in PostgreSQL advisory locks:
```python
async with session.begin():
    locked = await session.execute(text("SELECT pg_try_advisory_xact_lock(424242)"))
    if not locked.scalar():
        return  # Another worker already acquired the lock
    # Run streak checks / target generation
```

## 11. Resilient Fallback Exception Handling (P3)

### Problem
When local SQLite KB matching cannot answer a question, the server falls back to Qdrant vector retrieval + OpenAI (`QUIZ_MODEL`). If the OpenAI API key is missing, expired, or ratelimited, the request fails with an unhandled `500 Internal Server Error`.

### Proposed Solution
- Wrap the secondary RAG fallback in a structured try/except:
  - If external retrieval fails, return `{ "valid": false, "explanation": "This question cannot currently be verified by the knowledge base." }`.
  - Log an alert for operational monitoring without breaking the player's session.
